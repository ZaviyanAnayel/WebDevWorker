2. How It Works: Syntax, Format & Specification

The underlying engine of the ai code reviewer online relies on a hybrid of static analysis and machine‑learning inference. First, the tool tokenizes your source code using language‑specific grammars (JavaScript, Python, Java, Go, etc.). It then builds an abstract syntax tree (AST) that represents the structural hierarchy of your program. This AST is the foundation for rule‑based checks such as unreachable code, unused variables, and insecure API usage.

After the AST is generated, a lightweight neural network—packed into a WebAssembly module—examines code patterns against a training set of millions of open‑source projects. The model predicts potential logical errors, anti‑patterns, and performance bottlenecks that traditional linters might miss. All specifications are stored in a JSON schema that you can export via the AI Code Explainer for documentation purposes.

Supported formats include raw .js, .py, .java, .go, as well as bundled files like .zip or .tar.gz. The reviewer automatically extracts archives, respects .gitignore rules, and skips generated files (e.g., node_modules, dist). For configuration, you can provide a .wdvrc file that defines custom rule severity, whitelist patterns, and integration hooks for the AI Refactor tool.

Because the entire pipeline runs in the browser, the reviewer adheres to the same security model as any other client‑side app: sandboxed execution, no network requests, and strict CSP compliance. This guarantees that your proprietary code never leaves your machine, aligning with the privacy‑first philosophy of WebDevWorker.
