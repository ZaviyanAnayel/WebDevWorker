1. How prefers-color-scheme Works

Every modern operating system ships a light/dark appearance setting, and browsers expose it to CSS through the prefers-color-scheme media query. Wrap rules in @media (prefers-color-scheme: dark) and those styles apply automatically whenever the user's OS is in dark mode — no JavaScript, no toggle button, no cookies. It is the fastest way to ship a dark theme: you declare an alternate palette and the browser handles the switching, even when the user flips their OS setting at sunset.

The media query also supports light and no-preference values. You can design dark-first — dark palette as the base styles with @media (prefers-color-scheme: light) for light overrides — or the reverse. Either order works; what matters is that every color on the page is defined in both schemes: backgrounds, text, borders, shadows, and form controls. Anything you forget stays blindingly bright in dark mode, which is the single most common dark-mode bug in production.

Support is effectively universal: Chrome, Edge, Firefox, Safari, and mobile browsers have supported prefers-color-scheme since 2019–2020. Because it is pure CSS, it works before JavaScript loads and degrades gracefully in older browsers, which simply ignore the block. For many content sites, this one media query plus a well-chosen palette is the entire dark-mode implementation — but most product teams go further and add a manual override, which is where CSS custom properties come in.

/* Automatic dark mode — zero JavaScript required */
body {
  background: #ffffff;
  color: #1e293b;
}

@media (prefers-color-scheme: dark) {
  body {
    background: #0f172a;
    color: #e2e8f0;
  }
  a { color: #7dd3fc; }
  .card {
    background: #1e293b;
    border-color: #334155;
  }
}

2. Theming with CSS Custom Properties

Duplicating every rule inside a media query gets messy fast. The professional approach is to define your palette once as CSS custom properties on :root, use those variables everywhere, then redefine only the variables for dark mode. Components never change — only the tokens they reference do. This collapses a dark theme from hundreds of override rules into a single block of variable reassignments.

The standard pattern pairs a data-theme attribute on the <html> element with the OS media query. Define default variables for light mode, override them inside @media (prefers-color-scheme: dark), and also override them under html[data-theme="dark"] so a manual toggle can force either scheme regardless of the OS. The data-theme rule needs equal or higher specificity than the media-query rule so the user's explicit choice always wins.

Name variables by purpose, not by appearance: --bg-surface and --text-main beat --light-gray and --dark-blue, because values change meaning between themes while the purpose stays constant. A solid token set covers page background, surface backgrounds, primary text, muted text, borders, brand color, and state colors for success, warning, and danger — each tuned separately for light and dark so contrast stays comfortable in both.

:root {
  --bg-page: #ffffff;
  --bg-surface: #f1f5f9;
  --text-main: #0f172a;
  --text-muted: #64748b;
  --border: #e2e8f0;
  --brand: #2563eb;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg-page: #0f172a;
    --bg-surface: #1e293b;
    --text-main: #f1f5f9;
    --text-muted: #94a3b8;
    --border: #334155;
    --brand: #60a5fa;
  }
}

/* Manual override always wins over the OS setting */
html[data-theme="dark"] {
  --bg-page: #0f172a;
  --bg-surface: #1e293b;
  --text-main: #f1f5f9;
  --text-muted: #94a3b8;
  --border: #334155;
  --brand: #60a5fa;
}

3. Adding a Manual Theme Toggle

A manual toggle respects users who want your site dark while their OS is light, or vice versa. The implementation is small: a button flips data-theme on <html> between light and dark, and the choice is saved to localStorage so it persists across visits. On page load, an inline script in <head> reads the saved value before first paint and sets the attribute immediately — this is what prevents the white flash that plagues naive implementations.

When no saved preference exists, fall back to the OS setting with window.matchMedia('(prefers-color-scheme: dark)').matches. A polished toggle also listens for OS changes while the page is open and updates the theme live — unless the user has already made an explicit choice, which should always win over the automatic setting.

Accessibility matters here too: give the toggle an aria-label such as “Switch to dark mode”, reflect the current state with aria-pressed, and make sure the button itself remains visible in both themes. Place it in the site header or settings menu, where users expect theme controls to live.

<!-- Inline in <head>: runs before first paint, prevents theme flash -->
<script>
(function () {
  try {
    var saved = localStorage.getItem('theme');
    var theme = saved || (window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light');
    document.documentElement.setAttribute('data-theme', theme);
  } catch (e) {}
})();
</script>
// Theme toggle button logic
const btn = document.getElementById('themeToggle');

function setTheme(theme) {
  document.documentElement.setAttribute('data-theme', theme);
  try { localStorage.setItem('theme', theme); } catch (e) {}
  btn.setAttribute('aria-pressed', String(theme === 'dark'));
}

btn.addEventListener('click', () => {
  const current = document.documentElement.getAttribute('data-theme');
  setTheme(current === 'dark' ? 'light' : 'dark');
});

4. Polishing the Details: Images, Shadows, and Contrast

Colors are only half the battle. Photographs and illustrations keep full brightness in dark mode and can feel like headlights on a dark page. A light filter: brightness(0.85) on media in dark mode takes the edge off without mangling the image. For simple black line-art logos, filter: invert(1) flips them to white — but never invert photographs, which come out looking like x-ray negatives.

Shadows need rethinking too: a soft black drop shadow is invisible on a near-black background. In dark themes, favor subtle light borders or slightly lighter layered surfaces (cards a step above the page background) to create depth instead of relying on shadows. Borders in dark mode generally need to be a touch lighter than you expect to remain visible at all.

Do not forget native UI: form inputs, scrollbars, and selection colors follow the browser's own theme unless told otherwise. Adding <meta name="color-scheme" content="light dark"> lets the browser render scrollbars, checkboxes, and default form controls to match your theme. Setting the CSS color-scheme property on :root achieves the same for these native elements even when the meta tag is missed.

/* Tame bright media in dark mode */
@media (prefers-color-scheme: dark) {
  img.photo, video {
    filter: brightness(0.85) contrast(1.05);
  }
  .logo-mark {
    filter: invert(1); /* line-art logos only — never photos */
  }
  .card {
    box-shadow: none;              /* dark shadows vanish on dark bg */
    border: 1px solid var(--border);
  }
}

5. Dark Mode Best Practices and Pitfalls

Pure black (#000) backgrounds with pure white text cause halation — text appears to bleed — and strain eyes in dark rooms. Professional dark themes use very dark grays or deep blues such as #0f172a or #121212 with off-white text like #e2e8f0. Keep body text contrast at WCAG AA (4.5:1) minimum; muted secondary text is where most dark themes fail audits, so check it explicitly rather than eyeballing it.

Add a short transition on theme change (transition: background-color .2s, color .2s) so the flip feels intentional rather than jarring — but respect prefers-reduced-motion and skip the animation for users who request reduced motion. Test both themes side by side: open two windows, force one to each theme, and click through every page, modal, tooltip, and empty state.

Finally, remember that dark mode is a rendering concern, not a separate site: never fork content or features by theme, and never assume dark mode means nighttime — plenty of users run dark mode at noon. Ship the toggle, respect the OS, keep contrast honest, and your dark mode will feel native instead of bolted on.

6. Frequently Asked Questions (FAQs)

Does prefers-color-scheme work in all modern browsers?

Yes. Chrome, Edge, Firefox, Safari, and mobile browsers have supported it since 2019–2020, covering effectively all real-world traffic. It is pure CSS, so it works before JavaScript loads and degrades gracefully — browsers that do not understand it simply ignore the block.

Should my dark theme use pure black backgrounds?

Usually not. Pure black (#000) with white text causes halation, where text looks blurry, and feels harsh in dark rooms. Most professional dark themes use deep grays or blues like #0f172a or #121212 with off-white text (#e2e8f0), which is easier on the eyes while still looking properly dark.

How do I stop the page flashing white before dark mode applies?

Put a tiny inline script in <head> that reads the saved theme from localStorage and sets data-theme on <html> before first paint. Because it runs synchronously during parsing, the browser paints the correct theme on the very first frame — no flash, no framework needed.

Can I support the OS setting and a manual toggle together?

Yes, and you should. Default to the OS preference with matchMedia('(prefers-color-scheme: dark)'), then let an explicit toggle choice stored in localStorage override it. The manual rule (html[data-theme="dark"]) needs equal or higher specificity so the user's deliberate choice always wins.

Does dark mode affect SEO or page performance?

Not directly — search engines do not rank dark themes higher, and the CSS involved is trivial in size. Indirectly it helps: users who prefer dark mode stay longer and bounce less when a site respects their setting, and those engagement signals do matter for SEO.
