HTTP Status Codes Cheat Sheet: The Basics

HTTP status codes are three‑digit numbers returned by a web server to indicate the result of a client’s request. They are grouped into five classes:

  • 1xx – Informational: Request received, continuing process.
  • 2xx – Success: The request was successfully received, understood, and accepted.
  • 3xx – Redirection: Further action must be taken to complete the request.
  • 4xx – Client Error: The request contains bad syntax or cannot be fulfilled.
  • 5xx – Server Error: The server failed to fulfill a valid request.

These codes appear in HTTP response headers, browser developer tools, API logs, and SEO audit reports.

The Core Problem This Cheat Sheet Solves

Developers and SEOs often encounter cryptic codes like 422 vs 400 or 301 vs 302. Misinterpreting them leads to broken APIs, lost traffic, and wasted debugging time. This cheat sheet consolidates meanings, typical causes, and actionable fixes so you can quickly diagnose why a request failed and apply the correct remedy.

Common Use Cases for an HTTP Status Codes Cheat Sheet

  • API Development: Validate responses, map error handling, and document endpoints.
  • SEO Redirect Management: Ensure permanent (301) vs temporary (302) redirects are used correctly to preserve link equity.
  • Debugging Webhooks: Interpret webhook response codes (e.g., 200 vs 500) to improve reliability.
  • Uptime Monitoring: Set alerts based on specific status thresholds (e.g., 5xx spikes).

Troubleshooting and FAQ: HTTP Status Codes Cheat Sheet Answers

Q: What’s the difference between 404 and 410?

A: 404 Not Found means the resource is currently unavailable but may return later. 410 Gone signals the resource is permanently removed, prompting search engines to de‑index it faster.

Q: When should I use 301 vs 302 vs 307?

A: Use 301 for permanent URL changes (SEO value passes). 302 is for temporary moves where the original URL will return. 307 preserves the original HTTP method (e.g., POST) on a temporary redirect.

Q: How do 401 and 403 differ?

A: 401 Unauthorized indicates authentication is required or failed. 403 Forbidden means authentication succeeded but the client lacks permission to access the resource.

Q: What’s the distinction between 500, 502, and 503?

A: 500 is a generic server error. 502 Bad Gateway occurs when a server acting as a gateway receives an invalid response. 503 Service Unavailable means the server is overloaded or down for maintenance.

Q: How can I fix a 429 Too Many Requests error?

A: Implement exponential backoff, respect Retry-After headers, and consider rate‑limiting adjustments on the client side.

Q: What is the “I'm a teapot” 418 code?

A: 418 is an Easter‑egg from RFC 2324, originally a joke. Some APIs use it humorously to indicate an unexpected request.
