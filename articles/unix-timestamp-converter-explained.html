Understanding Unix Time: The Basics

Unix time, also known as epoch time, counts the number of seconds that have elapsed since 00:00:00 UTC on 1 January 1970. This single integer makes it easy for computers to store and compare dates without dealing with time zones or calendar quirks. For example, the Unix timestamp for 2024‑04‑01 12:00 UTC is 1711972800. The same moment expressed in milliseconds would be 1711972800000. Knowing the difference between seconds and milliseconds is essential when converting between epoch and human‑readable dates.

The Core Problem This Solves: Converting Epoch to Date

Raw timestamps are hard for humans to read. When debugging logs, inspecting API responses, or querying databases, you often see values like 1625097600 or 1625097600000. Without conversion, you can’t tell whether the value represents 2021‑07‑01 00:00 UTC or a completely different moment. The confusion between seconds and milliseconds adds another layer of difficulty, leading to off‑by‑three‑orders‑of‑magnitude errors in logs and UI displays.

Common Use Cases for an Epoch to Date Converter

  • Debugging API responses that return timestamps in seconds or milliseconds.
  • Viewing database fields that store Unix timestamps (e.g., MySQL INT columns).
  • Interpreting JWT exp claims, which are expressed as seconds since the epoch.
  • Scheduling jobs or cron tasks based on epoch values.
  • Analyzing log files where each entry is prefixed with a Unix timestamp.

Formulas and Technical Reference

Basic conversion formulas:

Be aware of the Year 2038 problem: 32‑bit signed integers overflow after 03:14:07 UTC on 19 January 2038. Use 64‑bit integers or store timestamps in milliseconds to avoid this.

Leap seconds are not counted in Unix time; they are ignored, so occasional one‑second jumps may appear when comparing to UTC‑based calendars.

// JavaScript: Convert epoch seconds to ISO string
function epochToISO(seconds) {
  return new Date(seconds * 1000).toISOString();
}
console.log(epochToISO(1711972800)); // 2024-04-01T12:00:00.000Z

# Python: Convert epoch milliseconds to datetime
import datetime
def epoch_ms_to_dt(ms):
    return datetime.datetime.utcfromtimestamp(ms / 1000.0)
print(epoch_ms_to_dt(1711972800000))
# 2024-04-01 12:00:00

Troubleshooting and FAQ

Why does my timestamp show 1970‑01‑01?

That date indicates the timestamp is zero (epoch start) or the value is too small. Check if you accidentally entered milliseconds as seconds.

How can I tell if a value is seconds or milliseconds?

If the number has 13 or more digits, it’s likely milliseconds; 10 digits usually means seconds. The converter auto‑detects, but you can also compare against the current epoch (≈1.7 × 109 seconds).

My converted date is in the wrong timezone. What gives?

Unix timestamps are always UTC. The displayed timezone depends on your browser or tool settings. Adjust the timezone selector in the Unix Timestamp Converter or apply an offset in code.

What does a negative Unix timestamp mean?

Negative values represent dates before 1970‑01‑01 UTC. For example, -86400 equals 1969‑12‑31 00:00 UTC.

What is “epoch 0”?

Epoch 0 is the reference point of Unix time: 00:00:00 UTC on 1 January 1970. All timestamps count seconds (or milliseconds) from this moment.

How do I avoid the Year 2038 overflow?

Store timestamps as 64‑bit integers or use milliseconds (which exceed the 2038 limit). Most modern languages and databases support 64‑bit types out of the box.
