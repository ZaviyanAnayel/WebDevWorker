2. How It Works: Syntax, Format & Specification

The JSON specification (ECMA‑404) defines a very small grammar: objects, arrays, numbers, strings, booleans, and null. Objects are unordered collections of name/value pairs, each name must be a double‑quoted string, and values can be any valid JSON type. Arrays are ordered lists of values. Whitespace is insignificant, which is why minified JSON can be a single line of characters.

A json formatter online parses the input using a recursive descent algorithm or a native JSON.parse() call. If parsing succeeds, the formatter re‑serialises the data with JSON.stringify(value, null, 2) (or a custom indent) to produce a pretty‑printed version. Validation occurs simultaneously: any syntax error throws an exception that the UI captures and displays with line/column details.

Key formatting rules enforced by the tool include:

  • Double quotes around all property names and string values.
  • No trailing commas after the last element in objects or arrays.
  • Proper escaping of control characters (e.g., \n, \t, \\).
  • Numeric values must not contain leading zeros unless the value is 0.
  • Unicode characters are preserved; optional pretty‑print can escape non‑ASCII if desired.

Because the formatter runs entirely in the browser, it leverages the native JavaScript engine for both parsing and stringification, guaranteeing compliance with the latest ECMAScript standards. This also means you can trust the output to be safe for downstream tools like the JSON to Go Struct Converter or the JSON to Python Pydantic Converter without additional transformation steps.

Best practices for reliable formatting:

  • Validate before committing. Run the formatter on every JSON file that enters version control.

  • Avoid comments. JSON does not support comments; strip them with the formatter to prevent parse errors.
