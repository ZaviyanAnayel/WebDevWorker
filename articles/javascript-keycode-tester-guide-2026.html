6. Frequently Asked Questions (FAQs)

Why is event.keyCode deprecated in modern JavaScript?

keyCode returned varying numeric numbers across different operating systems, browsers, and international keyboard layouts (QWERTY vs AZERTY). W3C standardized event.key and event.code to provide consistent, cross-platform strings.

What is the difference between event.key and event.code?

event.key represents the character generated taking into account Shift state and language layout (e.g. pressing 'a' returns 'a', but with Shift it returns 'A'). event.code represents the physical hardware key location regardless of language (e.g. always 'KeyA').

How do you detect the Command key on Mac and Ctrl on Windows?

Test both event.metaKey (Command on macOS) and event.ctrlKey (Control on Windows/Linux): const isCommand = e.metaKey || e.ctrlKey;.

Why does e.preventDefault() fail on certain browser shortcuts like Ctrl+W?

For security reasons, web browsers block web pages from overriding critical browser management shortcuts (such as closing tabs with Ctrl+W or exiting full-screen with Esc).

How do you handle keyboard accessibility for custom buttons?

Custom interactive elements (like &lt;div role="button"&gt;) must listen for both Enter and Space (e.key === 'Enter' || e.key === ' ') to satisfy WCAG 2.1 keyboard navigation criteria.
