6. Frequently Asked Questions (FAQs)

What is the difference between git reset --soft and git reset --hard?

git reset --soft rolls back the commit history but leaves your changed files staged in the index. git reset --hard rolls back the commit history AND permanently overwrites your working files on disk.

Why is --force-with-lease safer than git push --force?

--force blindly overwrites the remote branch even if another developer pushed new commits in the interim. --force-with-lease refuses to push if the remote branch reference has changed since your last fetch, preventing accidental destruction of peer work.

How can I recover a commit that was deleted via hard reset?

Run git reflog to locate the commit's SHA hash from your recent HEAD movement history. Then run git checkout -b recovery-branch <SHA> to restore your code into a new branch.

How do I safely squash multiple commits before a pull request?

Run git rebase -i HEAD~N (where N is the number of commits). In the interactive editor, leave the first commit as 'pick' and change subsequent commits to 'squash' or 's'.
