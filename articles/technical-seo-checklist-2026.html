1. Crawl & Indexation Controls

Crawl control is about spending Google's attention wisely. Every site gets a finite crawl budget — the number of pages Googlebot will fetch per day — and wasting it on junk means important pages get crawled late or not at all. The two instruments are robots.txt, which blocks fetching at the path level, and meta robots / X-Robots-Tag, which control indexing and snippet behavior per page or per response.

The classic trap is blocking a page in robots.txt while also wanting it deindexed. A disallowed page is never fetched, so Google never sees its noindex directive — and may still index the URL based on external links, showing a bare URL in results. The rule: robots.txt for "don't waste time fetching this" (admin areas, faceted filters, internal search), noindex for "fetch it, but keep it out of the index" (thank-you pages, thin archives, staging leftovers).

For non-HTML files — PDFs, images, API responses — the X-Robots-Tag HTTP header is the equivalent of the meta robots tag. Use it to noindex generated documents and to allow large image previews, as the snippet below shows.

# Apache: keep PDFs out of the index, allow large image previews
<FilesMatch "\.(pdf)$">
  Header set X-Robots-Tag "noindex, nofollow"
</FilesMatch>
<FilesMatch "\.(jpe?g|png|webp|avif)$">
  Header set X-Robots-Tag "max-image-preview:large"
</FilesMatch>

# nginx equivalent
location ~* \.pdf$ {
  add_header X-Robots-Tag "noindex, nofollow";
}

2. Canonical URLs and Duplicate Content

Duplicate content is rarely a penalty — it is a dilution problem. When the same content lives at five URLs (www vs non-www, HTTP vs HTTPS, trailing slash variants, UTM parameters), ranking signals split across them and none of the versions ranks as well as one consolidated page would. The canonical tag (rel="canonical") tells search engines which URL is the master copy that should accumulate all signals.

Canonicals must be absolute URLs, self-referencing on the master page itself, and consistent — never canonicalize page A to B while B canonicalizes back to A, and never point a canonical at a URL that redirects or 404s. Common legitimate uses: e-commerce sorting and filtering parameters, syndicated articles pointing back to the original, and HTTP/HTTPS or www/non-www consolidation.

Remember the hierarchy of strength: a 301 redirect beats a canonical tag, which beats leaving duplicates unresolved. If users should never land on the duplicate, redirect it. If the duplicate must stay live for users, canonicalize it.

<!-- On https://www.example.com/shoes/?sort=price_asc -->
<link rel="canonical" href="https://www.example.com/shoes/" />

<!-- Self-referencing canonical on the master page itself -->
<!-- On https://www.example.com/shoes/ -->
<link rel="canonical" href="https://www.example.com/shoes/" />

<!-- Syndicated copy points home -->
<!-- On partner-site.com/your-article -->
<link rel="canonical" href="https://www.example.com/articles/your-article/" />

3. Hreflang for Multilingual Sites

Hreflang tells Google which language and regional version of a page to show each searcher — so a user in Berlin gets the German page and a user in Toronto gets the Canadian English page instead of everyone landing on the US version. Without it, near-duplicate translated pages cannibalize each other and searchers bounce from the wrong language.

Implementation has strict rules that break silently. Annotations must be bidirectional: if the English page declares the German alternate, the German page must declare the English one back, or Google ignores both. Every language version — including the page itself — must be listed, and each should carry a self-referencing canonical. Use correct ISO codes (en-US, de-DE, fr-CA), and add an x-default entry as the fallback for unmatched locales.

For large sites, put hreflang in the XML sitemap instead of the HTML head — it keeps templates clean and scales to thousands of URLs. Either way, validate with Search Console's international targeting report after deployment.

<!-- Hreflang cluster: every page lists every version, bidirectionally -->
<!-- On https://www.example.com/en/pricing/ -->
<link rel="alternate" hreflang="en-US" href="https://www.example.com/en/pricing/" />
<link rel="alternate" hreflang="de-DE" href="https://www.example.com/de/preise/" />
<link rel="alternate" hreflang="fr-FR" href="https://www.example.com/fr/tarifs/" />
<link rel="alternate" hreflang="x-default" href="https://www.example.com/en/pricing/" />
<link rel="canonical" href="https://www.example.com/en/pricing/" />

4. HTTP Status Codes Done Right

Status codes are your site's body language to crawlers, and getting them wrong corrupts the index. A 200 says "here is content"; a 301 says "moved permanently, transfer authority"; a 302 says "temporary, keep the old URL indexed"; a 404 says "not here"; a 410 says "gone deliberately"; a 503 says "down temporarily, come back later." Each has precise SEO semantics — a 302 on a permanent move leaks authority for months.

The expensive mistakes: soft 404s (returning 200 with "not found" text) that fill the index with junk; redirect chains of three or more hops that bleed crawl budget; and serving 404 pages that are actually useful — a good 404 suggests alternatives and keeps the user, while a lazy one bounces them to a competitor. During maintenance or outages, always serve a 503 with a Retry-After header so Google pauses instead of deindexing.

Audit status codes quarterly with a crawler: every redirect should resolve in one hop, every canonical target should return 200, and no indexed URL should return anything but 200.

200 OKPage exists and is servedEligible for indexing
301 Moved PermanentlyURL moved foreverTransfers ~all ranking signals
302 FoundTemporary moveOld URL stays indexed — don't use for permanent moves

5. Redirects, HTTPS & the Full Audit Checklist

Redirects and HTTPS are the connective tissue of technical SEO. Every site migration, URL cleanup, or domain change needs a complete redirect map — old URL to new URL, one hop, 301 — tested before launch and monitored for 404 spikes after. Redirect chains accumulate silently over years of redesigns; flattening them is unglamorous work that measurably recovers crawl budget and speed.

HTTPS is table stakes: a valid certificate, HSTS to force secure connections, and no mixed content. Mixed active content (HTTP scripts on HTTPS pages) gets blocked by browsers and breaks functionality; mixed passive content (HTTP images) triggers warnings. Scan for hardcoded http:// asset URLs after every migration.

The quarterly audit checklist: crawl the full site and fix chains, loops, and 404s; verify canonicals are absolute and self-consistent; confirm robots.txt and sitemaps are valid; check hreflang bidirectionality; review Search Console coverage for excluded-but-valuable pages; and re-run Core Web Vitals. Ninety minutes, four times a year, prevents nearly every technical SEO disaster.

# Apache: single-hop, permanent redirects (no chains)
Redirect 301 /old-pricing https://www.example.com/pricing/
Redirect 301 /blog/2019/hello https://www.example.com/articles/hello/

# nginx: canonical host + HTTPS in one hop
server {
  listen 80;
  server_name example.com www.example.com;
  return 301 https://www.example.com$request_uri;
}

# HSTS: force HTTPS for one year, include subdomains
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

6. Frequently Asked Questions (FAQs)

What is the difference between robots.txt and noindex?

Robots.txt asks crawlers not to fetch a page at all, while noindex lets them fetch it but keeps it out of the index. Crucially, a page blocked by robots.txt can never see the noindex tag — so use noindex (not robots.txt) when you want a page crawled but not indexed.

When should I use a canonical tag vs a 301 redirect?

Use a 301 redirect when only one version should exist for users — the old URL is dead. Use a canonical tag when multiple versions must stay live (sorting, tracking parameters, syndication) but you want search engines to consolidate ranking signals onto one master URL.

Do I need hreflang if my site is English-only?

No. Hreflang is only for sites with multiple language or regional versions of the same content. A single-language site needs correct canonicals and geo-targeting in Search Console, not hreflang annotations.

How many redirects in a chain is too many?

Keep chains to a single hop. Google follows up to 5-10 redirects but each hop costs crawl budget, adds latency, and dilutes link equity slightly. Audit quarterly and flatten chains so every old URL points directly at its final destination.

Does HTTPS directly affect rankings?

Yes, HTTPS has been a confirmed lightweight ranking signal since 2014. More importantly, browsers label HTTP pages "Not Secure," which destroys user trust and conversions. There is no legitimate reason to serve public content over plain HTTP in 2026.
