1. The Five Position Values

static is the default: elements flow normally and top/right/bottom/left do nothing. relative keeps the element in flow but lets you nudge it with offsets — the space it originally occupied is preserved, which surprises beginners when gaps appear.

absolute removes the element from flow and positions it against its nearest positioned ancestor. fixed positions against the viewport (stays put on scroll). sticky is a hybrid: it flows normally until a scroll threshold, then sticks.

/* Dropdown anchored to its button wrapper */
.menu-wrap { position: relative; }
.menu {
  position: absolute;
  top: 100%; left: 0;   /* below the wrapper */
  z-index: 50;
}

2. The Containing Block Rule

An absolutely positioned element anchors to its nearest ancestor with a position other than static. No positioned ancestor? It anchors to the initial containing block (roughly the viewport). This single rule explains 90% of 'why is my dropdown in the wrong place' bugs.

The fix is a one-liner: add position: relative to the intended anchor. Transforms, filters, and will-change also create containing blocks — a common gotcha when an animated parent hijacks absolutely positioned children.

3. Z-Index and Stacking Contexts

z-index only works on positioned elements (and flex/grid items). But the real complexity is stacking contexts: a positioned element with a z-index creates an isolated stacking universe, and its children's z-indices can't escape it. That's why a modal with z-index: 9999 can still hide behind a header with z-index: 10.

Keep z-index values in a scale (10/20/30 or a token system), avoid magic numbers like 99999, and prefer DOM order + isolation for simple cases. When debugging, DevTools' 3D layer view reveals stacking contexts instantly.

4. Sticky: The Best of Both Worlds

position: sticky with top: 0 makes headers cling to the viewport top while their section is in view, then release naturally. No JavaScript, no scroll listeners — it replaced an entire category of jQuery plugins.

Two requirements trip people up: the sticky element needs a threshold (top, bottom, etc.), and no ancestor may have overflow: hidden (it kills stickiness by removing the scroll container). Table headers, TOC sidebars, and section navs are the classic wins.

/* Sticky table header */
thead th {
  position: sticky;
  top: 0;
  background: var(--bg-surface);
  z-index: 5;
}

5. Real-World Patterns and Pitfalls

Modals and toasts: fixed + full-viewport overlay + centered content. Tooltips: absolute inside relative wrappers. Sticky navs: sticky; top: 0 with a solid background and shadow on stick.

Common pitfalls: forgetting the positioned ancestor, z-index wars from magic numbers, fixed breaking inside transformed ancestors (it becomes absolute-like), and sticky failing under overflow: hidden parents. Learn these five and positioning stops being scary.

6. Frequently Asked Questions (FAQs)

What is the difference between relative and absolute positioning?

Relative keeps the element in document flow and offsets it from its normal position. Absolute removes it from flow and positions it against its nearest positioned ancestor.

Why is my z-index not working?

Either the element isn't positioned (z-index needs position other than static, or flex/grid item), or it's trapped inside a parent stacking context.

When should I use sticky vs fixed?

Sticky when the element should scroll naturally then cling within its section (headers, TOCs). Fixed when it must stay put regardless of scroll (modals, floating buttons).

Why did my sticky element stop working?

Usually an ancestor has overflow: hidden/auto/scroll, which breaks stickiness — or no top/bottom threshold was set.

Does transform affect positioned children?

Yes — transform, filter, and will-change create containing blocks, so absolutely positioned descendants anchor to that element instead of the expected one.
