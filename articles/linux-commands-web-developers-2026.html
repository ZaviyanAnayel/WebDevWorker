1. Navigating the Filesystem Like a Pro

Every server session starts with orientation: where am I, what is here, and how do I get where I need to go? These five commands answer those questions, and fluency with them is the difference between fumbling and flowing on a remote machine.

pwd                          # print working directory
ls -lah                      # list all files, human-readable sizes
cd /var/www/myapp && pwd    # jump somewhere, confirm
find /var/log -name "*.log" -mtime -1   # files changed in last day
tree -L 2 -I node_modules    # visual directory map

Learn the shortcuts: cd - jumps back to your previous directory, ~ is your home, and tab-completion finishes paths for you. Combine commands with && (run next only if the previous succeeded) to navigate and act in one line.

find deserves special attention — it searches by name, size, age, and type across entire trees. Hunting a runaway log file or a misplaced config starts here.

2. Files, Permissions, and Ownership

Linux's permission model protects your server: every file has an owner, a group, and three permission sets (owner, group, others) for read, write, and execute. ls -l shows them as -rw-r--r--; chmod changes them, using either symbols or octal numbers.

touch app.log                    # create empty file
cp -r src/ backup/               # copy recursively
mv old.js new.js                 # rename / move
rm -rf node_modules/             # delete recursively (careful!)

chmod 755 deploy.sh              # rwxr-xr-x: executable script
chmod 600 .env                   # rw-------: secrets, owner only
chown -R www-data:www-data /var/www/myapp

The two numbers to memorize: 755 for scripts and directories (everyone can read and enter, only you can modify) and 600 for secrets like .env files and private keys (only you can read). A private key readable by others will be refused by SSH — that is a feature, not a bug.

Remember rm -rf has no undo. Pair it with ls first, or use rm -i for interactive confirmation on unfamiliar servers.

3. Processes and System Monitoring

When a server slows down, you need to see what is running and what it is consuming. ps lists processes, top (or the friendlier htop) shows live resource usage, and systemctl manages services.

ps aux | grep node              # find Node processes
htop                            # interactive CPU/RAM monitor (q to quit)
kill -15 1234                    # polite: ask process 1234 to stop
kill -9 1234                     # force kill (last resort)

df -h                           # disk space by filesystem
du -sh /var/log/* | sort -rh | head   # biggest log consumers
free -h                         # memory usage

Prefer kill -15 (SIGTERM) over kill -9 (SIGKILL): the polite signal lets the process flush buffers and close connections, while -9 can corrupt data. Reserve force-kill for genuinely hung processes.

systemctl status nginx, restart, and enable manage services on modern distros — far more reliable than running daemons by hand in a terminal that might disconnect.

Watch for the usual suspects when load spikes: runaway Node processes eating RAM, disk-full log partitions, and zombie workers from crashed deploys. htop sorted by memory plus df -h diagnoses most slowdowns in under a minute.

4. Networking and Reading Logs

Debugging a web app on a server is mostly reading logs and checking connections. tail -f streams a log live, grep filters it, and curl tests endpoints without a browser.

tail -f /var/log/nginx/error.log        # watch errors live
journalctl -u myapp -f                   # systemd service logs, live
grep -i "error" app.log | tail -20       # last 20 error lines

curl -I https://example.com              # headers only
curl -s http://localhost:3000/health | jq .   # test local API
ss -tlnp | grep 3000                     # what listens on port 3000

The pipeline command | grep pattern | tail is the single most-used debugging shape in server work. Learn it, and most “the site is down” mysteries unravel in minutes: check the port listener, curl the app directly, then read the error log.

For structured logs, pipe through jq to query JSON fields instead of reading a thousand lines top to bottom: filter to errors first, then expand the surrounding context. It turns log archaeology into a thirty-second operation.

5. SSH, Cron, and Command Combos

Two tools round out the essentials: SSH for reaching servers and moving files, and cron for scheduling recurring work like backups and certificate renewals.

ssh user@server.com                      # connect
scp backup.tar.gz user@server.com:/tmp/   # copy file to server
rsync -avz ./dist/ user@server.com:/var/www/app/  # smart sync

# Cron: run backup daily at 2 AM (crontab -e)
0 2 * * * /home/user/backup.sh >> /var/log/backup.log 2>&1
CommandUse It For
sshSecure shell into remote servers
scp / rsyncCopy files to and from servers
cronSchedule scripts (backups, renewals)
grepSearch text in files and output
curlTest APIs and endpoints
tail -fWatch logs in real time
chmod / chownFix permissions and ownership
systemctlManage services (start, stop, enable)

Chain commands deliberately: && runs the next step only on success (deploy scripts), ; runs regardless, and pipes | feed one command's output into the next. These three connectors turn individual commands into real workflows.

6. Frequently Asked Questions (FAQs)

Do I really need to learn Linux as a web developer?

Yes. Nearly all production servers run Linux, and deploying, debugging, and securing your app happens over SSH on the command line. You do not need to be a sysadmin, but the commands in this guide cover 95 percent of daily server work.

What is the difference between sudo and su?

sudo runs a single command with administrator privileges and logs it; su switches your entire session to another user (usually root). Prefer sudo: it is auditable, does not require sharing the root password, and limits how long you operate with full power.

How do I find which process is using a port?

Run ss -tlnp | grep PORT or lsof -i :PORT. The output shows the process name and PID, which you can then inspect with ps or stop with kill.

What does chmod 755 actually mean?

Each digit sets read (4), write (2), and execute (1) permissions: 7 = 4+2+1 (read, write, execute) for the owner, 5 = 4+1 (read, execute) for the group and others. So 755 means the owner has full control while everyone else can read and execute.

How do I run a script automatically every day?

Add a line to your crontab with crontab -e, using the format minute hour day month weekday followed by the command. 0 2 * * * runs daily at 2 AM. Always use absolute paths in cron jobs and redirect output to a log file.
