1. Pseudo-Classes: Styling by State

Pseudo-classes style elements based on state rather than markup: :hover, :focus, :active, :disabled, :checked. They let interfaces react without JavaScript — a checkbox hack can power tabs, toggles, and accordions with pure CSS.

The accessibility star is :focus-visible: it shows focus rings only for keyboard navigation, not mouse clicks. In 2026, styling :focus alone (rings on every click) or removing outlines entirely are both considered bugs — :focus-visible is the correct primitive.

/* Accessible focus: keyboard users get rings, mouse users don't */
.btn:focus { outline: none; }
.btn:focus-visible {
  outline: 2px solid var(--brand-primary);
  outline-offset: 2px;
}
/* Pure-CSS toggle */
.toggle input:checked + .track { background: #10b981; }

2. Structural Pseudo-Classes

:nth-child(), :first-child, :last-child, and :only-child target elements by position among siblings. The an+b microsyntax (:nth-child(2n) for even, :nth-child(3n+1) for every third starting at first) handles striping, grids, and staggered animations.

Remember :nth-child counts all siblings, not just matching ones — li:nth-child(2) fails if the second child is a div. :nth-of-type() counts only siblings of the same element type, which is usually what you actually want.

3. Pseudo-Elements: ::before and ::after

Pseudo-elements style parts of elements: ::before and ::after generate decorative boxes without extra markup, ::first-letter creates drop caps, ::selection styles highlighted text, and ::placeholder styles input hints.

The generated-content workhorses require content: "" (even empty) to render. Classic uses: decorative underlines, custom bullets, quotation marks, clearfix replacements, and tooltip arrows — all without polluting HTML. Keep them decorative: content critical to understanding belongs in real markup for screen readers.

/* Decorative link underline that grows on hover */
.link {
  position: relative;
}
.link::after {
  content: "";
  position: absolute;
  left: 0; bottom: -2px;
  height: 2px; width: 100%;
  background: currentColor;
  transform: scaleX(0);
  transform-origin: right;
  transition: transform 250ms ease;
}
.link:hover::after {
  transform: scaleX(1);
  transform-origin: left;
}

4. Modern Gems: :is(), :where(), :has()

:is() groups selectors while taking the specificity of its most specific argument: :is(header, footer) a beats writing both out. :where() is identical but contributes zero specificity — perfect for resets and defaults that should be easy to override.

:has() — the 'parent selector' — styles an element based on its descendants: form:has(input:invalid) highlights invalid forms, .card:has(img) adjusts cards containing images. Supported in all modern browsers, it eliminated whole categories of JavaScript.

SelectorWhat it doesSpecificity note
:is(a, b)Matches eitherTakes max argument specificity
:where(a, b)Matches eitherAlways zero specificity
:has(> img)Parent with img childFull support in 2026
:not(.x)NegationTakes argument specificity

5. Specificity and Gotchas

Pseudo-classes count as classes in specificity; pseudo-elements count as elements. So a:hover (0,1,1) beats a (0,0,1) — which is why hover styles 'just work' when declared after base styles, and why :where() exists for when you want grouping without the boost.

Gotchas: ::before/::after don't work on replaced elements like <img> and <input> (no content box to attach to). Double-colon is the modern syntax; single-colon still works for legacy pseudo-elements but prefer :: in new code.

6. Frequently Asked Questions (FAQs)

What is the difference between : and :: in CSS?

Single colon denotes pseudo-classes (element states like :hover). Double colon denotes pseudo-elements (parts of elements like ::before). Legacy pseudo-elements accept single colon for backwards compatibility.

Why isn't my ::before showing up?

You probably forgot content: "" — generated pseudo-elements require a content property to render, even if empty. Also check it isn't on a replaced element like img or input.

What does :has() do?

It styles a parent based on its children — e.g. article:has(figure) targets articles containing figures. It's the long-awaited 'parent selector', supported in all modern browsers.

When should I use :where() instead of :is()?

Use :where() when you want selector grouping with zero specificity (resets, defaults). Use :is() when you want the natural specificity of the matched selectors.

Are pseudo-elements accessible to screen readers?

Generated content is generally announced inconsistently — keep ::before/::after decorative. Put meaningful content in real HTML elements.
