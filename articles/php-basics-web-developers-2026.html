1. How PHP Works: Server-Side Scripting in Plain English

PHP runs on the server, not in the browser. When a visitor requests a .php page, the server executes your PHP code, which typically outputs HTML, and the browser receives only the finished HTML — it never sees your source. That simple model is why PHP conquered the web: you mix code and markup in one file, upload it to nearly any shared host, and it just works.

Reports of PHP's death have been greatly exaggerated for over a decade. Modern PHP 8 is a different language from the PHP 5 tutorials still floating around: it has a just-in-time compiler, union types, attributes, match expressions, and a thriving ecosystem led by Laravel and Symfony. WordPress alone — built on PHP — still powers an enormous share of all websites, which keeps PHP skills commercially valuable.

To follow this guide you need PHP 8.1 or newer. The fastest local setup is XAMPP or Laragon for a full Apache-plus-MySQL stack, Docker if you prefer containers, or simply the built-in development server: run php -S localhost:8000 in your project folder and open http://localhost:8000 in a browser. No build step, no bundler, no waiting.

2. Syntax Essentials: Variables, Types, and Control Flow

PHP code lives inside <?php ... ?> tags; everything outside them is sent to the browser untouched. Variables always start with $ — $name = "Ayesha" — and PHP is dynamically typed, so a variable can hold a string now and an integer later. Statements end with semicolons, and the habit of writing them consistently will save you from half your parse errors.

Comparison deserves special attention: == compares loosely ("5" == 5 is true), while === compares strictly including type ("5" === 5 is false). Seasoned PHP developers default to === everywhere and only reach for == deliberately. Arrays are PHP's workhorse — they act as lists, dictionaries, and everything between — and foreach loops over them with a syntax you will use daily.

Functions like count(), strlen(), and in_array() cover most everyday needs, and the null coalescing operator ?? provides clean defaults: $page = $_GET["page"] ?? 1 reads as "page parameter, or 1 if missing." Modern PHP also supports arrow functions, named arguments, and return type declarations, closing most of the ergonomic gap with newer languages.

<?php
$name = "Ayesha";
$scores = [92, 85, 78];
$user = ["name" => "Bilal", "role" => "editor"];

// strict comparison: type AND value must match
if ($user["role"] === "editor") {
    echo "Welcome, " . $name . "!";
}

foreach ($scores as $i => $score) {
    echo "Test " . ($i + 1) . ": $score\n"; // variables expand in double quotes
}

$page = $_GET["page"] ?? 1;  // default to 1 when missing
?>

3. Superglobals: $_GET, $_POST, $_SERVER & $_SESSION

Superglobals are built-in arrays available in every scope without declaring them global — the reason you can read $_POST inside any function. $_GET holds URL query parameters (search.php?q=php), $_POST holds submitted form bodies, and $_SERVER carries request metadata like the request method, script path, and client IP. They are the bridge between the HTTP request and your code.

Sessions deserve their own spotlight: call session_start() at the top of your script and PHP gives you the persistent $_SESSION array, stored server-side and keyed to the visitor by a cookie. That is how login state survives page loads — you set $_SESSION["user_id"] = 42 once, and every later request knows who is browsing. Never store passwords or secrets in sessions; store the user ID and look the rest up.

Two more superglobals round out the set: $_COOKIE for reading browser cookies and $_FILES for handling uploads, each with quirks worth a dedicated guide. The golden rule for all of them is identical: treat every value as untrusted user input until you have validated or escaped it.

<?php
session_start();

// Reading query strings: search.php?q=php&page=2
$query = $_GET["q"] ?? "";
$page  = (int)($_GET["page"] ?? 1);

// Request metadata
$method = $_SERVER["REQUEST_METHOD"]; // GET or POST
$ip     = $_SERVER["REMOTE_ADDR"];

// Persistent login state
if (isset($_SESSION["user_id"])) {
    echo "Logged in as user #" . (int)$_SESSION["user_id"];
}
?>

4. Processing HTML Forms the Safe Way

A form with method="post" sends its fields to $_POST, keyed by each input's name attribute. Your handler's first job is validation: check required fields with empty(), verify email shape with filter_var($email, FILTER_VALIDATE_EMAIL), and cast numbers with (int). Client-side JavaScript validation improves UX but proves nothing — the server must re-check everything, because attackers bypass browsers entirely.

The second job is safe output. Any user-supplied value echoed into HTML must pass through htmlspecialchars($value, ENT_QUOTES), which converts <, >, quotes, and ampersands into harmless entities. Skip this step and a visitor can inject a <script> tag that runs in every other visitor's browser — the classic stored XSS attack, defeated by one function call.

Finally, follow the Post/Redirect/Get pattern: after handling a POST, send header("Location: thank-you.php") and exit instead of rendering HTML directly. Refreshing the result page then repeats a harmless GET instead of resubmitting the form — no duplicate comments, orders, or signups from an impatient F5 key.

<!-- contact.html -->
<form method="post" action="contact.php">
  <input type="text" name="name" placeholder="Your name" required>
  <input type="email" name="email" placeholder="Email" required>
  <button type="submit">Send</button>
</form>

<?php // contact.php
$name  = trim($_POST["name"] ?? "");
$email = trim($_POST["email"] ?? "");

if ($name === "" || !filter_var($email, FILTER_VALIDATE_EMAIL)) {
    die("Please provide a valid name and email.");
}

// ... save to database here ...

echo "Thanks, " . htmlspecialchars($name, ENT_QUOTES) . "!";
// then: header("Location: thank-you.php"); exit; // PRG pattern
?>

5. Functions, Includes & Organizing Your Code

Functions turn repeated logic into named, testable units. PHP 8 lets you declare parameter and return types — function add(int $a, int $b): int — which catches whole categories of bugs at the call site instead of deep in execution. Default parameter values, named arguments, and union types (int|float) make signatures expressive without getting verbose.

Includes solve the copy-paste problem of shared markup. Put your doctype, navigation, and footer in partials like header.php and footer.php, then pull them into each page with require "partials/header.php". Prefer require over include for essential files (it halts on failure instead of limping on), and require_once when a file defines functions or constants that must load exactly once.

A sane starter layout looks like this: public/ holding only index.php and assets (your web root), with src/ for functions and classes, partials/ for shared markup, and config.php for settings kept outside the document root where possible. This tiny bit of structure is the difference between a weekend script and a project you can still understand in six months.

<?php // src/helpers.php
declare(strict_types=1);

function greeting(string $name): string {
    return "Hello, " . htmlspecialchars($name, ENT_QUOTES) . "!";
}

function is_admin(array $user): bool {
    return ($user["role"] ?? "") === "admin";
}
?>

<?php // public/index.php
require_once __DIR__ . "/../src/helpers.php";
require "../partials/header.php";

echo greeting($_GET["name"] ?? "Guest");

require "../partials/footer.php";
?>

6. Frequently Asked Questions (FAQs)

Is PHP dead in 2026?

Not even close. PHP 8 is modern and fast, WordPress powers an enormous share of the web, and Laravel and Symfony run serious applications at major companies. Demand for PHP developers remains strong, especially in agencies, e-commerce, and content platforms.

Should I learn PHP, JavaScript, or Python?

It depends on your target. For server-rendered sites, WordPress work, or cheap shared hosting, PHP is unmatched. For single-page apps or data science, JavaScript or Python fit better. The PHP plus JavaScript combination remains one of the most employable stacks in web development.

Which PHP version should I learn?

Learn PHP 8.2 or 8.3: typed properties, union types, match expressions, attributes, and readonly classes. Avoid any tutorial still teaching mysql_* functions or PHP 5 patterns — that knowledge is obsolete and often insecure.

How do I run PHP on my own computer?

Install PHP directly from php.net, use XAMPP or Laragon for a complete Apache and MySQL stack, or run php -S localhost:8000 in your project folder for the zero-setup built-in development server.

Is PHP secure?

PHP itself is fine — insecurity comes from outdated patterns like concatenating user input into SQL or echoing it unescaped. Modern practices (PDO prepared statements, htmlspecialchars, password_hash) make PHP applications as secure as any other stack.
