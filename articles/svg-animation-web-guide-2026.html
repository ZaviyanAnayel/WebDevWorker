1. Three Ways to Animate SVG

SVG animations fall into three families. CSS animations apply keyframes to SVG elements exactly like HTML — transforms, opacity, and presentation attributes — with full access to easing, delays, and the cascade. SMIL (<animate>, <animateTransform>) is SVG's native declarative animation: no CSS or JS required, defined right in the markup. JavaScript (Web Animations API or libraries like GSAP) handles timelines, scrubbing, and physics that declarative approaches cannot express.

TechniqueStrengthsWatch out for
CSS keyframesFamiliar syntax, GPU-friendly transforms, easy statesLimited SVG attribute animation; transform-origin quirks
SMILZero dependencies, declarative, syncs with document timelineDeprecated in Chrome (still works); no IE-era support needed now
Web Animations APIImperative control, timelines, playbackRateMore code for simple effects
GSAPTimelines, morphing plugins, scrubbingLibrary weight; overkill for simple loops

For most UI motion — loaders, icon micro-interactions, draw-on effects — CSS is the sweet spot: it is composable with your existing stylesheets, respects prefers-reduced-motion naturally, and runs on the compositor when you animate transforms and opacity. Reach for SMIL when the SVG must animate standalone (an <img>-embedded SVG cannot run external CSS or JS, but SMIL inside it still plays).

2. CSS Animations on SVG Elements

SVG elements accept CSS transforms, but with one critical difference from HTML: the default transform-origin is the SVG viewport's origin (top-left of the canvas), not the element's center. Set transform-box: fill-box; transform-origin: center; and rotations behave intuitively around the element itself. This single declaration fixes the most common “my SVG spins around the wrong point” bug.

<svg viewBox="0 0 100 100" width="120" height="120">
  <circle class="spinner" cx="50" cy="50" r="40"
          fill="none" stroke="#eab308" stroke-width="8"
          stroke-linecap="round" stroke-dasharray="60 190" />
</svg>

<style>
.spinner {
  transform-box: fill-box;
  transform-origin: center;
  animation: spin 1.2s linear infinite;
}
@keyframes spin {
  to { transform: rotate(360deg); }
}

/* Pulse a notification dot — compositor-friendly */
.pulse {
  transform-box: fill-box;
  transform-origin: center;
  animation: pulse 2s ease-in-out infinite;
}
@keyframes pulse {
  0%, 100% { transform: scale(1); opacity: 1; }
  50%      { transform: scale(1.6); opacity: 0.4; }
}
</style>

CSS can also animate SVG presentation attributes that are mapped to CSS properties — fill, stroke, stroke-width, opacity, cx/cy/r for circles in modern browsers (geometry properties). Animating d (path data) via CSS works in Chromium when path commands match, but for reliable morphing across browsers, GSAP's MorphSVG or the Web Animations API remains the safer choice.

3. The Stroke-Dashoffset Draw Effect

The signature SVG animation — a line that draws itself — works by hiding a path behind its own dash pattern, then sliding the pattern away. Set stroke-dasharray to the path's total length (making one dash cover the whole path and one gap hide the rest), set stroke-dashoffset to the same length (pushing the visible dash off the path), then animate the offset to zero. The line appears to draw itself.

<svg viewBox="0 0 200 60" width="300">
  <path id="signature" d="M10 40 C 60 5, 120 5, 190 35"
        fill="none" stroke="#38bdf8" stroke-width="4"
        stroke-linecap="round" />
</svg>

<script>
  const path = document.getElementById("signature");
  const len = path.getTotalLength(); // exact path length, no guessing
  path.style.strokeDasharray = len;
  path.style.strokeDashoffset = len;
  // Trigger the draw (e.g. on scroll into view)
  path.getBoundingClientRect(); // force reflow
  path.style.transition = "stroke-dashoffset 1.8s ease-in-out";
  path.style.strokeDashoffset = "0";
</script>

Always measure with getTotalLength() rather than hard-coding values — paths change during design iteration, and a stale dash length produces a partially drawn line. For multi-path illustrations, stagger each path's transition delay by 150–300ms so the drawing unfolds sequentially. Pair the draw with a subtle fill fade-in (fill-opacity from 0) for a polished finish.

4. SMIL: Declarative Motion in Markup

SMIL embeds animation directly in SVG markup — no stylesheet, no script. <animate> tweens an attribute, <animateTransform> handles transforms, and <animateMotion> moves an element along a path. Timing attributes (begin, dur, repeatCount) choreograph sequences, and animations can trigger on events like begin="btn.click".

<svg viewBox="0 0 200 120" width="320">
  <!-- Ball bouncing along a path, looping forever -->
  <circle r="10" fill="#eab308">
    <animateMotion dur="3s" repeatCount="indefinite"
      path="M20,100 Q100,10 180,100" />
  </circle>

  <!-- Color pulse synced to the same timeline -->
  <rect x="20" y="20" width="40" height="40" rx="8" fill="#38bdf8">
    <animate attributeName="opacity" values="1;0.3;1"
             dur="3s" repeatCount="indefinite" />
    <animateTransform attributeName="transform" type="rotate"
      from="0 40 40" to="360 40 40" dur="6s" repeatCount="indefinite" />
  </rect>
</svg>

SMIL's reputation suffered when Chrome announced deprecation years ago — then walked it back; SMIL remains supported in all modern browsers in 2026. Its genuine superpower is portability: SMIL animations play inside SVG files loaded via <img>, in email clients that support SVG, and in exported assets where no CSS or JS can travel along. For standalone animated icons and logos, that makes SMIL uniquely valuable.

Limitations to respect: SMIL cannot be easily paused per-element from CSS, sequencing complex timelines gets verbose compared to GSAP, and animating with SMIL inside inline SVG duplicates what CSS does more maintainably. Use SMIL for portable assets; use CSS for in-page UI motion.

5. Performance and Accessible Motion

Animated SVG stays smooth when you animate the right properties. Transforms (translate, scale, rotate) and opacity run on the compositor without triggering layout or paint; animating stroke-dashoffset, fill, or geometry attributes forces repaints. For decorative loops this rarely matters, but a dashboard with fifty animated sparklines should stick to transform/opacity or move to Canvas.

/* Respect users who prefer reduced motion — non-negotiable */
@media (prefers-reduced-motion: reduce) {
  .spinner, .pulse, #signature {
    animation: none !important;
    transition: none !important;
  }
  #signature {
    stroke-dashoffset: 0 !important; /* show final state, not blank */
  }
}

/* Pause SMIL when reduced motion is preferred */
<script>
  if (matchMedia("(prefers-reduced-motion: reduce)").matches) {
    document.querySelector("svg").pauseAnimations();
  }
</script>

Accessibility is not optional garnish. Honor prefers-reduced-motion by disabling non-essential animation and showing end states (a draw-on path should appear fully drawn, not invisible). Give meaningful SVGs role="img" with a <title>, hide purely decorative ones with aria-hidden="true", and never convey critical information through motion alone — pair it with text or state changes screen readers can announce.

6. Frequently Asked Questions (FAQs)

What is the stroke-dashoffset draw effect?

It animates a path drawing itself: set stroke-dasharray to the path length, stroke-dashoffset to the same value to hide it, then transition the offset to zero. Measure the length with getTotalLength() so the effect stays exact.

Is SMIL deprecated?

No. Chrome announced deprecation years ago but reversed the decision, and SMIL is supported in all modern browsers in 2026. It remains the best choice for animations embedded in standalone SVG files where CSS and JS cannot run.

Why does my SVG rotate around the wrong point?

SVG's default transform-origin is the viewport origin, not the element center. Add transform-box: fill-box; transform-origin: center; to rotate around the element itself.

CSS or SMIL for SVG animation — which should I learn first?

Learn CSS first: it covers most UI motion, integrates with your stylesheets, and respects prefers-reduced-motion naturally. Add SMIL for portable standalone SVG assets that must animate without external CSS or JavaScript.

How do I make SVG animations accessible?

Honor prefers-reduced-motion by disabling non-essential motion and showing final states, use role=img with a title for meaningful graphics, aria-hidden for decorative ones, and never rely on motion alone to convey information.
