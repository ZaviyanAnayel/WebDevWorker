1. let, const, and Block Scoping

The var keyword declares function-scoped variables that hoist to the top of their function, which produced an entire generation of subtle bugs: loop counters leaking, accidental redeclarations, variables usable before their declaration line. ES6 replaced this model with let and const, which are block-scoped — they exist only inside the nearest curly braces — and cannot be used before declaration thanks to the temporal dead zone.

The rule of thumb is simple: default to const, use let only when reassignment is genuinely needed, and never use var in new code. const does not make values immutable — it makes the binding immutable. You can still push to a const array or mutate a const object's properties; you just cannot reassign the variable itself to something else. This catches an entire class of accidental-reassignment bugs at the moment they are written.

Block scoping also fixed the classic loop problem. With var, a for loop's counter was one shared variable, so asynchronous callbacks inside the loop all saw the final value. With let, each iteration gets its own binding, and closures capture the value you expect. If you only adopt one ES6 habit, make it this one — it eliminates more bugs per keystroke than any other feature on this list.

// var: function-scoped, hoisted, leaky
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var:', i), 10); // 3, 3, 3
}

// let: block-scoped, one binding per iteration
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let:', j), 10); // 0, 1, 2
}

const API_URL = 'https://api.example.com'; // never reassigned
let retries = 0;                            // reassigned later: fine
// API_URL = 'x'; -> TypeError: Assignment to constant variable

2. Arrow Functions and Template Literals

Arrow functions (=>) compress function expressions into a fraction of the code: single-expression bodies return implicitly, and single parameters can skip their parentheses. More importantly, arrows do not bind their own this — they inherit it lexically from the surrounding scope. That one change killed the const self = this; workaround that littered every pre-ES6 callback.

Template literals (backticks) ended string-concatenation spaghetti. ${} interpolates any expression directly into the string, and literals can span multiple lines without \n hacks or awkward plus-sign chains. They are the natural way to build HTML strings, log messages, and dynamic URLs — and tagged templates (a function prefixing the backtick string) power libraries like styled-components and lit-html under the hood.

One caution: arrow functions are not drop-in replacements everywhere. Because they lack their own this and arguments, they make poor object methods and event handlers that rely on dynamic this (use a regular function or method shorthand there), and they cannot be used as constructors. Reach for arrows in callbacks, array methods, and short utilities — exactly where lexical this is what you want.

// Arrow functions: concise + lexical `this`
const prices = [19.99, 4.5, 12.0];
const withTax = prices.map(p => p * 1.2);   // implicit return

class Cart {
  constructor() { this.items = []; }
  add(item) {
    // `this` inside the arrow = the Cart instance. No .bind() needed.
    setTimeout(() => this.items.push(item), 100);
  }
}

// Template literals: interpolation + multiline
const user = { name: 'Ayesha', orders: 3 };
const email = `
  Hi ${user.name},
  You have ${user.orders} orders shipping ${user.orders > 1 ? 'today' : 'tomorrow'}.
`;
console.log(email.trim());

3. Destructuring, Spread, and Rest

Destructuring unpacks arrays and objects into individual variables in one statement: const { name, email } = user; replaces three lines of property access. It shines in function parameters, where you can destructure the argument directly and supply defaults at the same time — function createUser({ name = 'Guest', role = 'member' } = {}) is self-documenting in a way positional parameters never were.

Spread (...) expands an iterable into individual elements, and rest (...) collects individual elements into an array — same syntax, opposite directions, distinguished by position. Spread clones and merges arrays and objects immutably ([...old, newItem], {...defaults, ...overrides}); rest gathers leftover function arguments (...args) or leftover object properties (const { id, ...rest } = record) without mutating the original.

Together these three make immutable updates ergonomic, which is why every React and Redux codebase leans on them. The mental model to keep: spread pours a collection out, rest scoops values up, and destructuring names what you scoop. Master that sentence and you will read modern JavaScript fluently.

// Destructuring with defaults + renaming
const response = { data: { id: 7 }, status: 200 };
const { data: { id: userId }, status = 500 } = response;
console.log(userId, status); // 7 200

// Spread: immutable merge & clone
const defaults = { theme: 'light', lang: 'en' };
const prefs = { ...defaults, theme: 'dark' }; // { theme:'dark', lang:'en' }
const queue = ['a', 'b'];
const next = [...queue, 'c'];                // queue untouched

// Rest: gather the leftovers
function log(level, ...messages) {
  console[level](`[${level}]`, ...messages);
}
log('warn', 'low disk', 'retrying...'); // [warn] low disk retrying...

4. Modern Essentials: Optional Chaining, Modules, and More

ES2020's optional chaining (?.) ended the pyramid of && guards: user?.profile?.avatar safely short-circuits to undefined instead of throwing when any link in the chain is missing. Its partner, nullish coalescing (??), supplies defaults only for null/undefined — unlike ||, it keeps meaningful falsy values like 0 and '' intact, which fixes a whole category of “setting vanished” bugs in configuration code.

ES modules (import/export) gave JavaScript a real module system: explicit dependencies, static analysis for tree-shaking, and no more script-tag ordering roulette. Default exports (export default) suit single-purpose modules; named exports suit utility collections and are friendlier to refactoring tools. Modern bundlers and browsers both speak ESM natively now, so new projects should start there.

Round out the toolkit with a few more ES6+ staples: default parameters, the for...of loop (which iterates values, unlike for...in which iterates keys), classes as sugar over prototypes, Promises and async/await for asynchronous work, and Set/Map for collections with sane semantics. You do not need all of them on day one — but recognizing each on sight is what separates reading modern code from guessing at it.

// Optional chaining + nullish coalescing
const settings = { volume: 0, theme: null };
const vol   = settings.volume ?? 50;  // 0  (kept! || would give 50)
const theme = settings.theme ?? 'dark'; // 'dark'
const avatar = user?.profile?.avatar ?? '/img/default.png';

// ES modules
// utils.js
export const TAX_RATE = 0.2;
export function withTax(price) { return price * (1 + TAX_RATE); }
export default function format(n) { return '$' + n.toFixed(2); }

// app.js
import format, { withTax, TAX_RATE } from './utils.js';
console.log(format(withTax(100))); // $120.00

5. ES6+ Feature Quick Reference

Use this table as a desk reference while you internalize the syntax. Each row pairs the feature with its most common real-world use so you can recognize the pattern in other people's code and reach for the right tool in your own.

A practical adoption order if you are modernizing an older codebase: first swap var for let/const, then convert callbacks to arrows, then introduce template literals and destructuring in new code, and finally adopt modules and optional chaining where they remove the most noise. Incremental migration beats big-bang rewrites.

Everything in this guide is supported natively in all current browsers, so no transpiler is required for browser-targeted code in 2026. Transpilation still matters only when you must support legacy environments — and even then, tools like esbuild handle it in milliseconds.

6. Frequently Asked Questions (FAQs)

When should I use const vs let?

Default to const for every declaration. Switch to let only when the variable genuinely needs reassignment later, like a counter or accumulator. Never use var in new code — its function scoping and hoisting cause bugs that let and const eliminate by design.

Do arrow functions have their own this?

No — that is their defining trait. Arrow functions inherit this lexically from the enclosing scope, which is why they are perfect for callbacks inside methods. For object methods or event handlers that need dynamic this, use a regular function or method shorthand instead.

What is the difference between spread and rest?

They are the same ... syntax used in opposite directions: spread expands a collection into individual elements ([...arr, x], f(...args)), while rest collects individual elements into an array (function f(...args), const { a, ...rest } = obj). Position in the code tells you which one you are looking at.

Is ES6 supported in all browsers now?

Yes. Every feature in this guide — including ES2020 additions like optional chaining — is supported natively in all current browsers. You only need a transpiler if you must support legacy environments such as Internet Explorer.

Should I still learn ES5 patterns?

Learn to recognize them, not to write them. You will encounter var, function expressions, and callback pyramids in older codebases, so understanding them helps you read and migrate legacy code — but all new code should use the modern equivalents.
