2. How It Works: Syntax, Format & Specification

The builder expects a concise specification written in a simple markup we call MicroSpec. Each block begins with a #App header, followed by #UI, #Logic, and optional #Style sections. The AI parses this structure, maps it to HTML elements, JavaScript event handlers, and CSS rules. Below is the formal grammar:

#App
Name: <string>
Description: <string>

#UI
- Element: <type> (e.g., button, input, div)
  ID: <identifier>
  Label: <string>
  Props: { key: value, ... }

#Logic
- On: <event> (e.g., click, change)
  Target: <ID>
  Action: <JS expression or function>

#Style (optional)
- Selector: <CSS selector>
  Rules: { property: value, ... }

When you submit this spec, the builder creates a single index.html file that includes:

  • <script type="module"> for modern browsers.
  • Scoped CSS inside a <style> tag to avoid global bleed.
  • Self‑contained event listeners attached via addEventListener.

Because the output is pure front‑end code, you can further enhance it with any of WebDevWorker’s other tools. For example, run the generated JavaScript through the AI Code Reviewer for a quick security audit, or use the AI Code Doctor to refactor for performance. The builder also respects existing libraries – you can import axios or lodash directly in the #Logic block.

Remember to keep the spec under 300 tokens for optimal generation speed. The AI model will truncate overly long descriptions, which can lead to incomplete code. Stick to clear, action‑oriented sentences and avoid ambiguous phrasing.

Example 2: Todo List with localStorage

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Todo Micro‑App</title>
  <style>
    ul { list-style:none; padding:0; }
    li { margin:4px 0; }
  </style>
</head>
<body>
  <input id="newItem" placeholder="Add task">
  <button id="addBtn">Add</button>
  <ul id="list"></ul>
  <script type="module">
    const list = document.getElementById('list');
    const input = document.getElementById('newItem');
    const load = () => JSON.parse(localStorage.getItem('todos')||'[]');
    const save = arr => localStorage.setItem('todos', JSON.stringify(arr));
    const render = () => {
      list.innerHTML = '';
      load().forEach((t,i)=>{
        const li=document.createElement('li');
        li.textContent=t;
        li.onclick=()=>{remove(i)};
        list.appendChild(li);
      });
    };
    const add=()=>{ if(input.value){ const arr=load(); arr.push(input.value); save(arr); input.value=''; render(); }};
    const remove=i=>{ const arr=load(); arr.splice(i,1); save(arr); render(); };
    document.getElementById('addBtn').onclick=add;
    render();
  </script>
</body>
</html>

By following these guidelines, you can ship micro‑apps that feel native, respect user privacy, and scale across thousands of internal users without a backend.

6. Frequently Asked Questions (FAQs)

What is an ai micro app builder and how does it differ from a full‑stack framework?

An ai micro app builder creates self‑contained front‑end bundles from a natural‑language spec. Unlike full‑stack frameworks it does not generate server code, routing, or database layers. The output runs 100% in the browser, making it faster to prototype and eliminating server‑side deployment.

Is the ai micro app builder truly client‑side only?

Yes. All AI inference runs in WebAssembly inside your browser. No data is sent to external servers, there is no signup, and the tool respects your privacy by keeping everything local.

Can I customize the generated code after the build?

Absolutely. The builder outputs plain HTML, CSS, and JavaScript. You can edit IDs, add libraries, or refactor logic. For advanced review, run the code through the AI Code Reviewer or AI Code Doctor for suggestions.

What are the size and performance limits of a micro‑app?

Best practice is to keep JavaScript under 5 KB and total bundle under 15 KB. Generation time stays below 1.5 seconds, and initial render is typically under 100 ms on mobile networks.

How do I ensure security for the generated micro‑app?

Run the output through the AI Security Auditor to detect XSS, CSP gaps, and unsafe DOM manipulation. Also avoid embedding user‑generated HTML directly; use textContent or sanitization libraries.

Can I integrate the micro‑app with existing back‑end APIs?

Yes. Include fetch calls in the #Logic section. Since the builder is client‑side only, you must handle CORS and authentication yourself, possibly using tokens generated by the AES Encryption/Decryption Tool.
