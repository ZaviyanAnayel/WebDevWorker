1. Selecting Elements: querySelector and Friends

Everything starts with selection. document.querySelector() takes any CSS selector and returns the first match; document.querySelectorAll() returns all matches as a static NodeList. These two cover the vast majority of real-world selection — if you can target it in CSS, you can grab it in JavaScript with the same string, which keeps your mental model unified.

The older methods still have their place: getElementById() is the fastest lookup on the page and reads clearly for unique elements, while getElementsByClassName() and getElementsByTagName() return live HTMLCollections that update automatically as the DOM changes. That liveness is a double-edged sword — convenient for polling, treacherous inside loops that mutate the DOM, where the collection shifts under your feet.

A practical rule: use querySelector(All) by default for its expressive power, getElementById for hot paths and singletons, and convert NodeLists to real arrays ([...nodes]) whenever you need map, filter, or other array methods. NodeList gained forEach years ago, but it is still not an Array — spread it first and stop thinking about it.

// querySelector: any CSS selector works
const form   = document.querySelector('#signup-form');
const inputs = document.querySelectorAll('.field input[required]');
const firstError = document.querySelector('.field.error');

// NodeList -> Array for full array powers
const values = [...inputs].map(i => i.value.trim());

// Scoped selection: search within an element, not the whole document
const card = document.querySelector('.product-card');
const price = card.querySelector('.price'); // only inside this card

2. Creating, Inserting, and Removing Nodes

To build DOM from JavaScript, create nodes with document.createElement(), configure them through properties (textContent, className, dataset), and insert them with append(), prepend(), before(), after(), or replaceWith(). These modern insertion methods accept multiple nodes and even plain strings, and they move nodes if the node already lives elsewhere — no separate “remove then insert” dance.

When inserting many nodes in a loop, never append directly to the live document each iteration: every insertion can trigger layout work. Instead, build into a DocumentFragment — a lightweight off-screen container — and append the fragment once. The browser performs a single reflow, and list-rendering code gets measurably faster with zero added complexity.

For removal, element.remove() deletes a node directly, while parent.replaceChildren() wipes all children in one call — cleaner than the old while (parent.firstChild) loop. And remember the security rule that matters most in this whole guide: assign user-controlled text with textContent, never innerHTML. innerHTML parses strings as HTML, which turns user input into a cross-site scripting (XSS) vulnerability; textContent treats it as inert text, always.

// Build a list efficiently with a DocumentFragment
const users = ['Ayesha', 'Bilal', 'Chen'];
const frag = document.createDocumentFragment();

for (const name of users) {
  const li = document.createElement('li');
  li.className = 'user';
  li.textContent = name;          // SAFE: text, not HTML
  li.dataset.username = name.toLowerCase();
  frag.append(li);                // off-screen: no reflow yet
}
document.querySelector('#user-list').append(frag); // one reflow

// DANGER: never do this with untrusted data
// element.innerHTML = userInput;  // XSS vulnerability!
// SAFE alternative for untrusted data:
element.textContent = userInput;

3. Events: Listeners and the Event Object

addEventListener() is how JavaScript hears the page: element.addEventListener('click', handler) registers a callback without clobbering existing ones, unlike the onclick property which allows exactly one handler. Always prefer addEventListener — libraries, analytics snippets, and your own code can all listen to the same event without fighting.

The third argument (an options object) is underused and powerful: { once: true } auto-removes a one-shot listener, { passive: true } tells the browser the handler will not call preventDefault() so touch scrolling stays smooth, and { capture: true } runs the handler in the capture phase. Pair addEventListener with removeEventListener (same function reference required — anonymous callbacks cannot be removed) to avoid leaks in single-page apps.

Every handler receives an event object carrying the details: event.target is the element the event originated on, event.currentTarget is the element the listener is attached to, and methods like preventDefault() (stop the default action) and stopPropagation() (stop the event traveling further) give you control over behavior. Understanding target vs currentTarget is the key that unlocks event delegation, covered in depth in our dedicated guide.

const btn = document.querySelector('#save-btn');

function onSave(event) {
  event.preventDefault();               // stop form submission / navigation
  console.log(event.target);            // the clicked element
  console.log(event.currentTarget);     // #save-btn (listener owner)
  saveDraft();
}

// once: perfect for one-shot actions like onboarding tooltips
document.querySelector('#tour-start')
  .addEventListener('click', startTour, { once: true });

// passive: keeps touch scrolling buttery on mobile
document.addEventListener('touchmove', onTouchMove, { passive: true });

// Cleanup in SPAs: named function references can be removed
btn.removeEventListener('click', onSave);

4. Traversing and Updating Efficiently

Selection finds a starting point; traversal walks from there. parentElement, children, firstElementChild, nextElementSibling, and closest(selector) let you navigate the tree relatively — closest() is the star, climbing ancestors until one matches a selector, which makes “find the card this button belongs to” a one-liner. Prefer the Element variants (children over childNodes) to skip text nodes and comments.

For updates, classList is the modern workhorse: add, remove, toggle (with an optional force boolean), and contains replace all string surgery on className. Toggle with a condition — el.classList.toggle('active', isActive) — syncs UI state to a boolean in one readable line. For styles, set individual properties via el.style or swap classes; reserve direct style manipulation for truly dynamic values like drag positions.

Performance comes down to one principle: batch reads and writes. Alternating “read layout, write style, read layout” forces the browser to recalculate layout synchronously each time (layout thrashing). Read everything first, then write everything: measure all elements, then apply all changes. For animations, move work to transform and opacity — the two properties the compositor can animate without layout or paint.

// closest(): "which card does this button belong to?"
document.querySelectorAll('.card .delete-btn').forEach(btn => {
  btn.addEventListener('click', () => {
    btn.closest('.card').remove();
  });
});

// classList.toggle with a force flag: sync UI to state
function setLoading(isLoading) {
  document.body.classList.toggle('is-loading', isLoading);
}

// Batch reads, then writes: no layout thrashing
const heights = [...document.querySelectorAll('.panel')]
  .map(el => el.getBoundingClientRect().height); // READ phase
document.querySelectorAll('.panel').forEach((el, i) => {
  el.style.setProperty('--h', heights[i] + 'px'); // WRITE phase
});

5. DOM Methods Cheat Sheet

Keep this table handy while you work. It groups the methods you will reach for daily by task, with a note on the one subtlety most likely to bite you for each group.

Two habits separate comfortable DOM programmers from frustrated ones: defaulting to textContent for any string that touched a user, and defaulting to event delegation (one listener on a parent) over attaching listeners in a loop. Both are covered with full examples in the code sections above and in our event delegation guide.

The DOM API is larger than any cheat sheet, but these twenty-odd methods handle the overwhelming majority of production work. When you need more — ranges, observers, shadow DOM — the same patterns apply: select precisely, mutate in batches, and clean up listeners you no longer need.

6. Frequently Asked Questions (FAQs)

Should I use querySelector or getElementById?

Use querySelector by default — one expressive API for any CSS selector keeps code uniform. Reach for getElementById in hot paths or for true singletons, where its direct lookup is marginally faster and the intent (“this id is unique”) reads clearly.

Is innerHTML dangerous?

With untrusted data, yes — it parses strings as HTML, so user input becomes executable markup (XSS). Use textContent for any string that touched a user; reserve innerHTML for trusted template strings you wrote yourself, and even then prefer DOM creation methods for clarity.

How do I remove all child nodes from an element?

Use parent.replaceChildren() — one call, no loop. The classic while (parent.firstChild) parent.removeChild(parent.firstChild) still works but is obsolete. Note that listeners attached to removed children are garbage-collected only if nothing else references them.

Why is my dynamically added button not clickable?

Its listener was attached before the button existed. Fix it with event delegation: attach one listener to a stable parent and check event.target (or use closest()) inside the handler. Delegated listeners automatically cover elements added later.

How do I avoid layout thrashing?

Never interleave layout reads (offsetHeight, getBoundingClientRect) with writes (style changes) in a loop. Batch: read all measurements first, then apply all mutations. For animations, stick to transform and opacity, which skip layout and paint entirely.
