1. What a Reverse Proxy Is — and Why Your App Needs One

Your Node.js app listens on port 3000, but users type https://yourapp.com — no port, encrypted, fast. A reverse proxy is the server software sitting in front of your app that makes that possible. It receives every request and forwards it to the right backend service.

Nginx is the industry-standard choice, and it earns its place: it terminates TLS so your Node app never handles certificates, serves static files far faster than Node can, compresses responses, caches aggressively, and load-balances across multiple app instances. One Nginx server on ports 80 and 443 can front a dozen different apps by domain or path.

The alternative — exposing Node directly — means handling SSL in every app, restarting the world to renew certificates, and serving every image through JavaScript. A reverse proxy separates concerns: Nginx handles the web, Node handles your application logic.

It also buys you operational superpowers for free: blue-green deployments by swapping upstream backends, A/B testing by routing percentages of traffic, and maintenance pages served instantly while your app restarts. All of it configured in text files, version-controlled alongside your infrastructure.

2. Installing Nginx and Learning the Config Layout

On Ubuntu or Debian, installation is one command. Nginx's configuration lives in /etc/nginx/: nginx.conf sets global behavior, while individual sites go in sites-available/ and are activated by symlinking into sites-enabled/.

# Install and verify
sudo apt update && sudo apt install -y nginx
sudo nginx -t          # test config syntax
sudo systemctl reload nginx

# Create a site and enable it
sudo nano /etc/nginx/sites-available/myapp
sudo ln -s /etc/nginx/sites-available/myapp /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

Always run nginx -t before reloading — it validates syntax without touching the running server, so a typo can never take your site down. Here is the skeleton every site config starts from:

server {
    listen 80;
    server_name example.com www.example.com;
    root /var/www/example.com;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

Keep each site in its own file and use descriptive names — api.example.com is clearer than default six months later. The symlink pattern lets you disable a site instantly by removing the link and reloading, without deleting its configuration.

3. Proxying Requests to Your Node.js App

The magic directive is proxy_pass. This config forwards everything to a Node app on port 3000, while forwarding the headers your app needs for correct IPs, protocol detection, and WebSockets:

server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket support
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
DirectiveWhat It Does
proxy_passBackend URL to forward requests to
proxy_set_headerHeaders sent to the backend app
X-Forwarded-ForOriginal client IP chain
X-Forwarded-ProtoOriginal protocol (http/https)
Upgrade / ConnectionEnables WebSocket proxying
proxy_read_timeoutHow long to wait for backend response

In Express, add app.set('trust proxy', 1) so req.ip and secure cookies respect the X-Forwarded-* headers. Without it, rate limiters see Nginx's IP for every user.

For multiple app instances, define an upstream block and let Nginx load-balance across them — the simplest path to horizontal scaling. Combine it with PM2 cluster mode or Docker replicas, and one small server can absorb traffic spikes that would flatten a single Node process.

4. Free SSL with Let's Encrypt

Certbot automates everything: it obtains a free Let's Encrypt certificate, installs it in your Nginx config, and sets up auto-renewal. Your Node app never touches TLS.

# Install Certbot's Nginx plugin and get a certificate
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d example.com -d www.example.com

# Certificates auto-renew; verify the timer works
sudo certbot renew --dry-run

Certbot rewrites your server block to listen on 443 with the certificate and adds an HTTP-to-HTTPS redirect. Renewals happen automatically via a systemd timer — the number one cause of “expired certificate” incidents is a broken renewal timer, so that dry-run check is worth its weight in gold.

For wildcard certificates covering all subdomains, use the DNS-01 challenge with your provider's plugin instead of the HTTP challenge. It requires API access to your DNS, but one certificate then secures api., app., and every future subdomain automatically.

5. Caching, Rate Limiting, and Hardening

Once the proxy works, make it fast and safe. Cache static or semi-static responses, rate-limit abusive clients, and add security headers — all in Nginx, before requests ever reach Node:

# Rate limiting: 10 requests/second per IP, burst of 20
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

server {
    listen 443 ssl;
    server_name api.example.com;

    location / {
        limit_req zone=api burst=20 nodelay;
        proxy_pass http://localhost:3000;
        proxy_cache my_cache;
        proxy_cache_valid 200 60s;
    }

    # Security headers
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options DENY always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;
}

Enable gzip for text responses, keep Nginx updated, and never proxy /.git or server-status endpoints publicly. A hardened reverse proxy is the cheapest security upgrade a small deployment can make.

Finally, log deliberately: keep access logs for traffic insight and error logs at warn level for signal without noise. Good logs turn the next 2 AM incident from a mystery into a ten-minute fix.

6. Frequently Asked Questions (FAQs)

What is the difference between a forward proxy and a reverse proxy?

A forward proxy sits in front of clients, hiding who is making requests (like a corporate proxy or VPN). A reverse proxy sits in front of servers, hiding the backend infrastructure from clients. Nginx in this guide is a reverse proxy.

Can Nginx serve static files and proxy an API at the same time?

Yes, with multiple location blocks. Serve your frontend build from disk in location /, proxy /api/ to Node, and Nginx routes each request correctly. This is the standard setup for single-page apps with a Node backend.

How do I proxy WebSockets through Nginx?

Set proxy_http_version 1.1 and forward the Upgrade and Connection headers, as shown in the config above. Without these headers, WebSocket handshakes fail with a 400 or hang indefinitely.

Do I still need PM2 if I use Nginx?

Yes. Nginx is a reverse proxy, not a process manager. PM2 keeps your Node app running, restarts it on crashes, and manages multiple instances for load balancing. They solve different problems and work best together.

Why does Nginx return 502 Bad Gateway?

Almost always because the backend is unreachable: your Node app is not running, it listens on a different port or interface than proxy_pass expects, or a firewall blocks localhost connections. Check the app first, then sudo tail -f /var/log/nginx/error.log.
