1. Setting Up React Router in a Modern App

React Router is the de facto routing library for React SPAs: it maps URLs to components, manages history, and gives you declarative navigation. Modern React Router (v6.4+) is built around a data router — you define routes as objects with loaders and actions, and the router handles data fetching, mutations, and pending states alongside navigation.

import { createBrowserRouter, RouterProvider } from 'react-router-dom';

const router = createBrowserRouter([
  { path: '/', element: <Home /> },
  { path: '/about', element: <About /> },
]);

// Mount once at your app root — everything below can use routing hooks
function App() {
  return <RouterProvider router={router} />;
}

createBrowserRouter uses the HTML5 history API for clean URLs (/about, no hash). If you deploy to a static host without server rewrites, every deep link 404s on refresh — either configure the server to serve index.html for unknown paths or fall back to createHashRouter during development. The older <BrowserRouter> component API still works, but the data router unlocks loaders, actions, and the best error handling, so prefer it for new apps.

Install with npm install react-router-dom and define routes centrally — a single route config is easier to audit for auth rules and code-splitting than routes scattered across components. Colocate each route's loader and component in the same file so data requirements live next to the UI that needs them.

2. Defining Routes: Elements, Links, and Navigation

Routes pair a path with an element. Navigation uses <Link> (client-side, no full reload) instead of <a>, and <NavLink> adds active-state styling for menus. Relative links resolve against the current route, which keeps nested UIs portable:

import { Link, NavLink, Outlet } from 'react-router-dom';

function Navbar() {
  return (
    <nav>
      {/* Client-side navigation: no page reload, state preserved */}
      <Link to="/">Home</Link>
      <Link to="/products">Products</Link>
      {/* NavLink knows when its route is active — perfect for menus */}
      <NavLink
        to="/dashboard"
        className={({ isActive }) => (isActive ? 'link active' : 'link')}
      >
        Dashboard
      </NavLink>
      {/* Relative link: resolves against the parent route's path */}
      <Link to="settings">Settings</Link>
    </nav>
  );
}

Dynamic segments use the colon syntax — /products/:productId — and match greedily in definition order, so put specific routes before wildcards. The index prop marks a route as the default child rendered when the parent path matches exactly. And path="*" is your catch-all for 404 pages.

One habit that prevents bugs: never use raw <a href> for in-app navigation. It triggers a full document reload, wiping React state, scroll restoration, and any pending transitions. Reserve anchor tags for genuinely external URLs and downloads.

3. Nested Routes and Shared Layouts

Nested routes are React Router's killer feature: a parent route renders a layout (sidebar, header, tabs) with an <Outlet /> placeholder where the matched child renders. The layout mounts once and persists while children swap — no re-fetching the sidebar on every tab click:

import { Outlet } from 'react-router-dom';

const router = createBrowserRouter([
  {
    path: '/dashboard',
    element: <DashboardLayout />,   // header + sidebar, rendered once
    children: [
      { index: true, element: <Overview /> },      // /dashboard
      { path: 'reports', element: <Reports /> },   // /dashboard/reports
      { path: 'reports/:reportId', element: <ReportDetail /> },
      { path: 'settings', element: <Settings /> }, // /dashboard/settings
    ],
  },
]);

function DashboardLayout() {
  return (
    <div className="dashboard">
      <Sidebar />      {/* persists across child navigation */}
      <main>
        <Outlet />     {/* matched child renders here */}
      </main>
    </div>
  );
}

Children paths are relative by default — 'reports' under /dashboard becomes /dashboard/reports — which makes route subtrees relocatable: move the whole dashboard under /admin by changing one parent path. Loaders compose too: parent loaders run before child loaders, so the layout can fetch the user while the child fetches its own data, all in parallel where independent.

Use nesting for any UI with persistent chrome: dashboards, settings pages, multi-step wizards, and tabbed detail views. If a section of UI never changes while the URL segment after it does, that's a layout route waiting to happen.

4. Dynamic Params, Search Params, and Programmatic Navigation

URL params (:productId) identify which resource; search params (?sort=price) describe how to display it — filters, sorting, pagination. Both are reactive: changing them re-renders the route, and search-param changes don't remount the component, so preserve scroll and local state accordingly:

import {
  useParams, useSearchParams, useNavigate, useLocation,
} from 'react-router-dom';

function ProductPage() {
  const { productId } = useParams(); // /products/:productId
  const [searchParams, setSearchParams] = useSearchParams();
  const sort = searchParams.get('sort') ?? 'popular';
  const navigate = useNavigate();
  const location = useLocation();

  const changeSort = (next) => {
    // Updates ?sort= without remounting — shareable, bookmarkable filter state
    setSearchParams({ sort: next }, { replace: true });
  };

  const goToCheckout = () => {
    // Programmatic navigation: after login, form submit, etc.
    navigate('/checkout', {
      state: { from: location.pathname }, // pass data without URL params
      replace: false,                     // true = replace history entry
    });
  };
}
Hook / ComponentReads or doesTypical use
useParams()Dynamic segments (:id)Which resource to show
useSearchParams()Query stringFilters, sort, pagination
useNavigate()Imperative navigationRedirect after submit/login
useLocation()Current URL + stateBreadcrumbs, "return here" flows
<Navigate>Declarative redirectRoute guards, legacy URLs
useMatch()Test a path patternConditional UI by route

Prefer search params over component state for anything the user might share or bookmark — filters in the URL survive refreshes and can be pasted into chat. And pass transient data (like "came from checkout") via navigation state rather than stuffing it into the URL.

5. Data Loading, 404s, and Protected Routes

Data routers colocate fetching with routes through loaders: functions that run before the route renders, whose return value arrives via useLoaderData(). Navigation waits for loaders, errors route to the nearest errorElement, and pending states come free — no more useEffect fetch waterfalls:

import { useLoaderData, Navigate, Outlet } from 'react-router-dom';

async function productLoader({ params }) {
  const res = await fetch('/api/products/' + params.productId);
  if (res.status === 404) throw new Response('Not found', { status: 404 });
  if (!res.ok) throw new Error('Failed to load product');
  return res.json();
}

function ProductPage() {
  const product = useLoaderData(); // data is ready — no loading state needed
  return <ProductDetail product={product} />;
}

// Route guard: redirect unauthenticated users, preserving destination
function RequireAuth() {
  const user = useCurrentUser();
  if (!user) return <Navigate to="/login" replace state={{ from: location.pathname }} />;
  return <Outlet />;
}

const router = createBrowserRouter([
  { path: '/products/:productId', element: <ProductPage />,
    loader: productLoader, errorElement: <ProductError /> },
  { element: <RequireAuth />, children: [
    { path: '/account', element: <Account /> },
  ]},
  { path: '*', element: <NotFound /> }, // catch-all 404
]);

Throwing a Response from a loader renders the nearest errorElement instead of crashing — that's your per-route 404 and error boundary in one. For protected routes, wrap private routes in a guard layout that renders <Navigate> when unauthenticated; stashing the original destination in navigation state lets the login page send users back where they were headed.

Finally, handle the scroll and focus basics: React Router restores scroll on back/forward automatically, and you should move focus to the new page heading on navigation for screen-reader users. Routing isn't done until keyboard and assistive-tech users can follow it too.

6. Frequently Asked Questions (FAQs)

Should I use React Router or Next.js file-based routing?

Use React Router when building a client-rendered SPA, embedding React in an existing site, or needing full control over the routing setup. Choose Next.js App Router when you want server rendering, server components, and SEO-friendly pages with zero routing configuration.

How do I protect routes so logged-out users can't access them?

Create a guard layout component that checks authentication and renders when unauthenticated, otherwise renders . Nest all private routes under it, and pass the original destination in navigation state so login can redirect back.

How do I read URL parameters in a component?

Use useParams() for dynamic segments like /products/:productId, and useSearchParams() for query strings like ?sort=price&page=2. Both are reactive: the component re-renders when the URL changes.

What is an Outlet in React Router?

Outlet is the placeholder where a parent layout route renders its matched child route. It enables nested routes with persistent UI — the layout mounts once while children swap inside the outlet on navigation.

How do I show a 404 page for unknown URLs?

Add a catch-all route with path="*" rendering your NotFound component at the end of your route config. For data routers, you can also throw a Response with status 404 from a loader to render the route's errorElement.
